# 小米汽车门户与后台火山引擎部署技术方案

> **版本:** v1.1
> **日期:** 2026-09-17
> **状态:** 待评审
> **关联文档:** [门户网站 Spec](../specs/2026-09-17-xiaomi-car-portal-spec.md) | [后台管理系统 Spec](../specs/2026-09-17-xiaomi-car-admin-spec.md) | [测试总计划](../testing/2026-09-17-test-plan.md)

---

## 1. 目标与约束

本方案覆盖小米汽车门户网站、独立后台管理系统、共享 Node.js API、MySQL、Redis、媒体资源、真实短信、微信 OAuth、监控和发布链路在火山引擎上的生产部署。

设计目标:

- 单地域、跨可用区部署,消除计算、数据库和缓存单点。
- 门户、后台和 API 使用独立域名及安全策略。
- 手机验证码必须通过火山引擎短信服务真实下发并接收状态报告。
- 用户密码、验证码、Token、短信和微信密钥不得进入代码、镜像或明文配置。
- 首期支持水平扩容,但不引入 Kubernetes、消息队列等非必要复杂度。
- 按 100 名用户同时在线且持续操作的生产负载设计,并承受 200 并发的短时突发。
- 中国内地公网服务上线前完成域名备案、公安备案和隐私合规检查。

## 2. 架构决策

### 2.1 推荐方案

采用“静态前端 + 双可用区 ECS 应用集群 + 托管数据服务”:

```text
门户用户
  │
  ├── www.example.com ── CDN ── TOS(web 静态资源)
  │
  ├── media.example.com ── CDN ── TOS(车型与内容图片)
  │
  └── api.example.com ── WAF ── ALB(HTTPS)
                                  │
                    ┌─────────────┴─────────────┐
                    │                           │
              ECS App-AZ1                ECS App-AZ2
              API + Worker               API + Worker
                    │                           │
                    └─────────────┬─────────────┘
                                  │ VPC 私网
                  ┌───────────────┼────────────────┐
                  │               │                │
           RDS MySQL 双节点   Redis 主备版       TOS 私有桶
              跨可用区          跨可用区         媒体/备份

运营人员
  │
  ├── admin.example.com ── CDN ── TOS(admin 静态资源)
  └── api.example.com/api/admin/* ── WAF ── ALB ── ECS

外部服务
  ├── 火山引擎短信服务: SendSms + 状态报告回调
  └── 微信开放平台: OAuth 授权与服务端 code 换取身份

可观测性
  ├── CloudMonitor: 云资源指标与告警
  ├── TLS: ALB、应用、安全与审计日志
  └── VMP(推荐): Node.js 自定义业务指标
```

该方案适合首期业务:前端无服务器运维,API 可水平扩容,数据库和缓存由云服务托管。ECS 比 VKE 初期成本和运维复杂度更低,同时保留 Docker 镜像迁移到 VKE 的路径。

### 2.2 未选择方案

| 方案 | 结论 | 原因 |
|------|------|------|
| 单台 ECS 承载前端、API、MySQL | 不用于生产 | 存在单点,备份、扩容和故障恢复风险高 |
| VKE 容器服务 | 规模增长后采用 | 首期服务数量少,引入集群、Ingress 和工作负载治理成本偏高 |
| Serverless 全量改造 | 暂不采用 | 现有 Express 长连接 SSE、事务任务和运行模型需额外改造 |

### 2.3 100 人并发容量模型

“100 人并发”定义为 100 名已建立会话且在同一时间窗口持续浏览、登录、查询库存或操作后台的用户,不是累计注册用户数。容量计算采用以下生产流量模型:

| 指标 | 设计值 | 说明 |
|------|--------|------|
| 同时在线用户 | 100 | 约 95 名门户用户 + 5 名后台运营人员 |
| 动态 API 稳态 | 50 RPS | 按活跃用户平均每 2-3 秒发起一次动态请求并增加余量 |
| 动态 API 短时峰值 | 100 RPS | 页面切换、批量刷新或活动开始时的瞬时流量 |
| 冲击测试 | 200 并发,持续 5 分钟 | 验证 2 倍并发余量和恢复能力 |
| 业务写入峰值 | 5 TPS | 注册、验证码校验、预约、下定及后台操作合计 |
| Dashboard SSE | 10 条长连接 | 覆盖后台人员和临时运维查看 |
| 短信提交 | 稳态 2 RPS,短时 5 RPS | 仍受手机号/IP 业务限流和供应商配额约束 |
| 动态响应体 | 平均不高于 50 KiB | 100 RPS 时应用层下行约 40 Mbps |
| 首屏静态资源 | 单用户不高于 3 MiB | 100 人同时首次访问约 300 MiB,由 CDN 承担 |

静态 JS、CSS、字体和车型图片由 CDN 命中后不进入 ECS。API 资源按单台 ECS 可承接全部 100 并发设计,正常双机运行时单台负载不高于设计容量的 50%,为节点故障和滚动发布保留余量。

## 3. 需要开通的火山引擎服务

### 3.1 生产必选

| 服务类型 | 火山引擎产品 | 用途 | 首期建议 |
|----------|--------------|------|----------|
| 账号与权限 | 访问控制 IAM | 人员、CI/CD、ECS 角色和最小权限策略 | 按 `dev/test/prod` 项目隔离,禁用共享主账号日常操作 |
| 网络 | 私有网络 VPC、子网、安全组 | 隔离公网接入、应用和数据层 | 1 个生产 VPC,至少 2 个可用区子网 |
| 公网入口 | 应用型负载均衡 ALB | HTTPS 终止、健康检查、API 七层转发 | 公网多可用区实例,80 强制跳转 443 |
| 计算 | 云服务器 ECS | 运行 Docker 化 Node.js API 和 Worker | 2 台跨可用区,每台 `2C4G`;单台需通过 100 并发压测 |
| 数据库 | 云数据库 MySQL 版 | 业务主数据、订单、库存、审计 | MySQL 8.0 双节点,主备跨可用区,初始 `2C8G` |
| 缓存 | 缓存数据库 Redis 版 | 分布式限流、OAuth state、缓存、SSE 广播 | 主备实例,跨可用区,初始 1-2 GiB |
| 对象存储 | 对象存储 TOS | 前端构建物、车型图片、CMS 媒体 | web/admin/media 分桶或分前缀,生产桶开启版本控制 |
| 内容加速 | 内容分发网络 CDN | 门户、后台静态文件和媒体加速 | 回源 TOS,启用 HTTPS、压缩和缓存规则 |
| 域名与证书 | 云解析 DNS、证书中心 | 域名解析、TLS 证书生命周期 | `www`、`admin`、`api`、`media` 四个子域名 |
| 短信 | 短信服务 | 注册、登录、微信绑定验证码 | 国内验证码消息组、签名、3 个模板和状态报告回调 |
| 密钥与凭据 | 密钥管理系统 KMS + 凭据管理 Secret Manager | 保存数据库口令、JWT、短信和微信凭据 | 独立生产凭据,限制 ECS 角色读取,配置轮换 |
| 日志 | 日志服务 TLS | 聚合应用、ALB、访问、安全与审计日志 | 按环境和日志类型拆分 Topic,建立索引与保留期 |
| 监控 | 云监控 CloudMonitor | ECS、ALB、MySQL、Redis、TOS、CDN 指标告警 | 配置告警联系人组、分级通知和可用性看板 |
| 镜像 | 镜像仓库 CR | 保存 API/Worker 容器镜像 | 私有仓库,不可变版本标签,生产仅允许内网拉取 |
| 安全 | Web 应用防火墙 WAF | SQL 注入、XSS、CC、Bot 和 API 防护 | 接入 `api` 和 `admin`,短信与登录接口单独限频 |

### 3.2 推荐开通

| 服务 | 用途 | 启用时机 |
|------|------|----------|
| 托管 Prometheus VMP | Node.js 请求耗时、错误率、事件循环、短信成功率、订单指标 | 联调环境即接入,生产启用告警 |
| 持续交付 Code Pipeline | 自动构建、测试、推镜像、灰度部署和回滚 | 团队暂无既有 CI/CD 平台时 |
| 操作审计 | 记录云资源配置和权限变更 | 生产账号启用 |
| 云安全中心 | ECS 漏洞、基线和入侵检测 | 生产上线前 |
| NAT 网关 | 私网 ECS 统一访问短信、微信、依赖仓库等公网服务 | ECS 不绑定公网 IP 时,生产推荐 |

### 3.3 按规模或风险启用

| 服务 | 适用条件 |
|------|----------|
| 容器服务 VKE | API/Worker 拆分为多个服务、发布频繁或需要自动扩缩容 |
| 弹性伸缩 AS | ECS 模式出现明显周期性峰值时 |
| 消息队列 RocketMQ | 短信、审计、缓存失效、订单过期任务需要可靠异步解耦时 |
| DDoS 原生防护 | 公网攻击风险或活动流量显著增长时 |
| 数据传输服务 DTS | 数据迁移、持续同步或跨地域灾备时 |
| 云调度 GTM | 双地域容灾和 DNS 级自动切换时 |

## 4. 资源与网络设计

### 4.1 地域和可用区

- 生产选择目标用户占比最高且上述产品均已开服的中国内地地域,例如华北 2 或华东 2;最终以采购时控制台为准。
- ECS、MySQL 主备和 Redis 主备至少跨两个可用区。
- 测试环境可以单可用区降本,不得与生产共享数据库、Redis、TOS 桶或密钥。
- 首期采用单地域多可用区,RPO 目标不高于 5 分钟,RTO 目标不高于 30 分钟。跨地域灾备另行立项。

### 4.2 子网和访问控制

| 网络区 | 放置资源 | 入站规则 |
|--------|----------|----------|
| 公网接入层 | ALB、NAT 网关 | 互联网仅允许 80/443;80 跳转 HTTPS |
| 应用子网 AZ1/AZ2 | ECS App/Worker | 仅允许 ALB 到应用端口;运维走堡垒或受控通道 |
| 数据子网 AZ1/AZ2 | MySQL、Redis | 仅允许应用安全组访问 3306/6379 |

- ECS 不绑定公网 IP,出站经 NAT 网关访问火山短信和微信接口。
- MySQL、Redis 关闭公网访问,白名单仅包含应用子网或应用安全组。
- 后台 API 在 WAF 增加 IP 白名单或企业零信任接入;登录接口仍执行 MFA、CSRF 和应用限流。
- TOS 媒体桶禁止公共写入。上传由 API 签发短时凭证或服务端转存,完成文件头、MIME、大小和像素校验后才发布。

### 4.3 域名

| 域名 | 目标 | 缓存 |
|------|------|------|
| `www.example.com` | CDN → TOS web | 带 hash 静态资源长期缓存,HTML 不缓存或短缓存 |
| `admin.example.com` | CDN → TOS admin | 静态资源长期缓存,HTML 短缓存 |
| `media.example.com` | CDN → TOS media | 图片长期缓存,更新使用新对象 key |
| `api.example.com` | WAF → ALB → ECS | 禁止 CDN 缓存动态 API 和 SSE |

微信开放平台回调固定为 `https://api.example.com/api/auth/wechat/callback`。短信状态报告使用带高熵令牌的独立回调 URL,令牌不得出现在日志中。

## 5. 应用部署

### 5.1 进程划分

- `api`:Express REST API 和 Dashboard SSE,无本地会话状态。
- `worker`:过期订单释放、缓存失效和可重试后台任务。
- 两类进程使用同一版本镜像、不同启动命令。首期可同机运行,但必须独立进程和健康检查。
- ALB 健康检查使用 `/health/live`;就绪检查 `/health/ready` 验证必要配置和依赖连通性,但不执行高成本查询。
- 优雅停机先从 ALB 摘除,停止接收新请求,等待活动请求和 SSE 连接排空后退出。

### 5.2 无状态与一致性

- Refresh Token 状态存 MySQL,Redis 只做缓存,不得成为会话唯一事实来源。
- 订单、库存、内容发布和验证码消费以 MySQL 事务为最终一致性边界。
- 短信限流、登录限流、OAuth state 和 SSE fan-out 使用 Redis。
- Worker 使用 MySQL 行锁或数据库租约抢占任务,确保双实例不会重复释放订单。
- Redis 故障时,登录与短信发送应 fail closed;普通内容缓存回退 MySQL;订单事务不依赖 Redis 正确性。

### 5.3 初始规格

| 环境 | ECS | MySQL | Redis | 说明 |
|------|-----|-------|-------|------|
| 开发 | 本地或 1 台 `2C4G` | 小规格单节点 | 可本地 | 不承载真实用户 |
| 测试/UAT | 常态 1 台 `2C4G`,性能验收临时扩至 2 台跨 AZ | 常态小规格,性能验收使用生产同规格双节点 | 1 GiB 主备 | 必须可构造 100/200 并发,使用独立短信测试配置 |
| 生产首期 | 2 台 `2C4G` 跨 AZ | 双节点 `2C8G`,100 GiB 起 | 主备 1 GiB | 支撑 100 并发、100 RPS 峰值及单机接管 |
| 增长阶段 | 2-4 台 `4C8G` 或迁移 VKE | 升配/增加只读节点 | 扩容或分片 | 持续并发超过 200 或触发性能阈值时 |

最终规格以生产等价环境压测结果为准。若单台 `2C4G` 无法满足第 10 节验收指标,上线前直接调整为每台 `4C8G`,不得依赖上线后临时升配。

### 5.4 进程、连接池与超时

- 每台 `2C4G` ECS 启动 2 个 API Worker,充分使用 2 个 vCPU;后台任务使用独立低并发 Worker。
- 每台 ECS 的 API MySQL 连接池合计上限为 20,即 2 个 API Worker 各 10;后台 Worker 上限为 5。双机连接池合计上限 50。数据库最大连接数至少为 100,并保留不低于 30% 的运维和故障切换余量。
- 每台 ECS 的 Redis 连接池上限为 20,使用连接复用,禁止每请求新建连接。
- API 普通读取超时 5 秒,业务写入超时 10 秒;调用短信和微信时设置独立连接/响应超时并进行有限重试。
- ALB 使用最少连接或轮询调度,不启用会话保持;应用保持无状态。
- 单个 API 实例设置并发保护和请求队列上限,过载时返回 `503` 并携带 `Retry-After`,避免拖垮 MySQL。

## 6. 短信与微信集成

### 6.1 火山引擎短信

开通步骤:

1. 开通短信服务并创建国内验证码消息组。
2. 申请企业短信签名。
3. 分别申请注册、登录、绑定手机号模板。
4. 配置短信状态报告 HTTPS 回调地址。
5. 创建最小权限调用身份,优先使用临时凭证;必须使用 AK/SK 时存入 Secret Manager 并轮换。
6. 配置发送额度、异常用量和失败率告警。

应用约定:

- 生产固定 `SMS_PROVIDER=volcengine`;非测试环境禁止 mock Provider。
- 调用 `SendSms` 时将内部 `request_id` 放入 `Tag`,状态报告中的 `ext` 用于关联业务请求。
- 记录火山引擎 `RequestId` 和每个号码对应的 `MessageID`,不记录验证码或完整手机号。
- API 调用成功仅表示提交受理;最终送达状态以异步状态报告为准。
- 回调按 `MessageID` 幂等,校验高熵回调令牌、账号、消息组、业务关联和重放时间窗;处理成功返回 HTTP 200。回调体中的 `signature` 是短信签名名称,不能当作请求验签字段。
- 回调公网可达,但只开放该固定路径并启用 WAF 访问控制、限频和日志审计。

关键配置:

```text
SMS_PROVIDER=volcengine
VOLCENGINE_SMS_REGION=cn-north-1
VOLCENGINE_SMS_ACCOUNT=
VOLCENGINE_SMS_SIGN=
VOLCENGINE_SMS_REGISTER_TEMPLATE_ID=
VOLCENGINE_SMS_LOGIN_TEMPLATE_ID=
VOLCENGINE_SMS_BIND_TEMPLATE_ID=
VOLCENGINE_SMS_CALLBACK_TOKEN=
```

短信 AccessKey ID/SecretKey、`SMS_CODE_PEPPER` 和回调令牌从 Secret Manager 读取,不以普通环境变量明文固化在 ECS 或流水线中。

### 6.2 微信 OAuth

- 在微信开放平台登记生产域名和回调地址,测试与生产使用独立应用配置。
- `WECHAT_APP_SECRET` 存入 Secret Manager;浏览器端仅使用公开的 AppID 和后端生成的授权地址。
- OAuth `state` 存 Redis,一次性消费,有效期建议 10 分钟。
- 后端换取身份后只保存必要的 OpenID/UnionID,不持久化微信 Access Token 和 Refresh Token。
- 微信接口不可用时返回可重试错误,不得绕过首次登录手机号绑定。

## 7. 数据、安全与合规

### 7.1 数据保护

- MySQL 开启自动数据备份和 Binlog,保留至少 14 天并支持按时间点恢复。
- 每季度执行一次恢复演练,结果记录恢复点、耗时和数据校验结果。
- TOS 媒体桶开启版本控制、服务端加密和生命周期规则;误删恢复窗口至少 30 天。
- Redis 仅保存可重建数据;不将其作为订单、库存或会话吊销的唯一存储。
- 手机号、OpenID/UnionID、IP 和操作审计按数据分类分级设置访问权限与保留期。

### 7.2 身份与密钥

- 人员通过 IAM 用户/角色访问,生产变更启用 MFA,不共享账号。
- ECS 使用实例角色访问 TOS、TLS、Secret Manager 等服务,避免静态 AK/SK。
- CI/CD 使用独立机器人身份,仅可推送指定 CR 仓库和更新目标实例。
- JWT 密钥、数据库口令、短信凭据、微信 AppSecret 至少每 90 天评审或轮换。
- Secret Manager 读取、KMS 解密、IAM 策略和生产发布操作全部纳入审计。

### 7.3 WAF 基线

- 启用 OWASP 常见漏洞防护、SQL 注入和 XSS 规则。
- 对 `/api/auth/sms-code`、`/api/auth/login`、微信回调和管理端登录分别设置限频。
- 先观察后拦截新规则,避免业务误杀;高置信规则直接阻断。
- 源站安全组只允许 ALB 访问,避免绕过 WAF 直连 ECS。

## 8. 可观测性与告警

### 8.1 日志

应用输出 JSON 到 stdout,由采集器写入 TLS。统一字段:

`timestamp`, `level`, `service`, `env`, `requestId`, `route`, `statusCode`, `latencyMs`, `userIdHash`, `adminId`, `errorCode`。

禁止写入密码、验证码、Token、Cookie、完整手机号、微信 Token、AK/SK。建议保留期:

- 应用与访问日志:30-90 天。
- 管理员审计日志:至少 180 天,具体以合规要求为准。
- WAF 和安全日志:至少 180 天或按安全制度执行。

### 8.2 核心指标

| 类别 | 指标 |
|------|------|
| 流量 | ALB QPS、4xx/5xx、P50/P95/P99、健康实例数 |
| 应用 | Node.js CPU/内存、事件循环延迟、连接池、SSE 连接数 |
| 数据库 | CPU、连接使用率、磁盘、IOPS、复制延迟、慢查询 |
| Redis | CPU、内存、连接数、命中率、拒绝连接、主从切换 |
| 业务 | 注册成功率、下定成功率、库存冲突、订单过期任务延迟 |
| 短信 | 提交成功率、送达成功率、供应商延迟、错误码分布 |

### 8.3 最低告警集

- ALB 5xx 连续 5 分钟超过 1%。
- API 读取接口 P95 连续 10 分钟超过 500 毫秒,或写接口 P95 超过 800 毫秒。
- 动态 API 持续超过 80 RPS 时触发容量预警,超过 100 RPS 时进入扩容评估。
- ALB 健康 ECS 少于 2 台。
- 任一 ECS CPU 超过 70% 或内存超过 80% 持续 10 分钟。
- MySQL CPU、连接或磁盘超过 80%,出现复制异常或备份失败。
- Redis 内存超过 75%、连接失败或发生主从切换。
- 短信提交成功率低于 98% 或送达成功率明显偏离 7 日基线。
- 订单过期任务延迟超过 5 分钟。

P0/P1 告警通过电话/短信加即时通讯通知,P2 通过即时通讯或邮件。告警必须包含环境、资源、时间、看板和处置手册链接。

## 9. CI/CD 与发布回滚

### 9.1 流水线

1. 拉取固定提交并安装锁定依赖。
2. 执行 lint、单元测试、API 集成测试和依赖漏洞扫描。
3. 构建 web/admin 静态产物和 API Docker 镜像。
4. 以提交 SHA 标记镜像并推送 CR;禁止复用生产 Tag。
5. 数据库变更执行向前兼容 migration,先扩展后收缩。
6. 滚动更新一台 ECS,通过健康检查和冒烟测试后更新第二台。
7. 上传前端产物至版本化 TOS 前缀,切换发布指针并刷新 HTML/CDN 缓存。
8. 自动执行短信测试号码、微信回调、登录、下定和后台 Dashboard 冒烟验证。

### 9.2 回滚

- API 回滚到上一不可变镜像;数据库 migration 必须兼容前后两个应用版本。
- 前端回切上一 TOS 发布前缀,只刷新 HTML 和入口文件。
- 配置通过 Secret Manager 版本回退,不得手工覆盖后无法审计。
- 出现数据错误时停止写流量,按既定恢复点执行 MySQL 恢复并进行业务校验。

## 10. 100 人并发性能验收

压测必须在与生产拓扑一致的 UAT 环境进行,流量经过 CDN、WAF 和 ALB,后端使用独立的 MySQL 双节点和 Redis 主备实例。建议使用 k6 或等价工具执行以下场景:

| 场景 | 负载模型 | 验证目标 |
|------|----------|----------|
| 基准负载 | 5 分钟从 0 升至 100 并发,持续 30 分钟 | 稳态容量、延迟、错误率和资源水位 |
| 峰值流量 | 动态 API 固定 100 RPS,持续 10 分钟 | 页面集中刷新时不排队失控 |
| 冲击负载 | 1 分钟升至 200 并发,持续 5 分钟后恢复 100 | 2 倍并发下可用且 2 分钟内恢复基线 |
| 单机故障 | 100 并发时从 ALB 摘除 1 台 ECS | 剩余节点接管,无人工介入 |
| 库存竞争 | 100 个并发请求争抢最后 1 个库存 | 仅 1 个订单成功,无超卖和重复订单 |
| SSE 稳定性 | 10 条 SSE 连接持续 60 分钟 | 无连接泄漏,指标更新延迟不高于 5 秒 |
| 短信链路 | mock 压测 + 受控真实号码抽样 | 验证限流、Provider 契约和真实送达,不批量骚扰真实号码 |

### 10.1 通过标准

| 指标 | 100 并发目标 | 200 并发冲击目标 |
|------|--------------|------------------|
| API 读取 P95 / P99 | `≤300 ms / ≤800 ms` | `≤800 ms / ≤1500 ms` |
| API 写入 P95 / P99 | `≤500 ms / ≤1200 ms` | `≤1200 ms / ≤2500 ms` |
| 技术性 5xx 错误率 | `<0.1%` | `<1%` |
| ECS CPU | 双机各 `<65%` | `<85%`,结束后 2 分钟内回落 |
| ECS 内存 | 各 `<75%`,无持续增长 | `<85%`,无 OOM |
| MySQL CPU / 连接使用率 | `<60% / <60%` | `<80% / <75%` |
| Redis CPU / 内存 | `<50% / <60%` | `<75% / <70%` |
| 单 ECS 故障 | 30 秒内完成流量摘除,业务 5xx `<1%` | 不要求与冲击场景同时执行 |

业务校验失败、主动限流产生的 `4xx/429` 单独统计,不得计入技术性 5xx,但必须符合预期规则。短信供应商和微信接口的外部延迟单独分桶,避免掩盖内部 API 性能。

### 10.2 流量脚本比例

100 个虚拟用户按以下比例随机执行,测试数据使用独立账号和可重复清理的经销商库存:

- 45% 浏览车型、内容和媒体。
- 20% 查询经销商及库存。
- 10% 登录、刷新 Token 和读取个人中心。
- 10% 创建或查询 0 元订单。
- 5% 创建或查询试驾预约。
- 5% 后台 Dashboard、用户、订单和库存查询。
- 5% 后台内容、库存和订单写操作。

短信发送接口不按上述比例直接调用真实通道。性能压测使用满足同一 Provider 契约的测试实现;上线验收再以受控真实手机号完成发送、接收和状态报告闭环。

## 11. 容量、成本与演进

成本优先级:

1. 生产保留双 ECS、双节点 MySQL、主备 Redis 和 ALB,不以降级高可用换取成本。
2. 开发/测试按时启停 ECS,使用较小规格和较短日志保留期。
3. 静态内容使用 TOS + CDN,减少 ECS 公网带宽和应用负载。
4. 初期不采购 VKE、RocketMQ、GTM 和跨地域数据库;达到触发条件再启用。
5. 通过资源标签 `project=xiaomi-ev`, `env`, `owner`, `cost-center` 实施分账。

演进触发条件:

- ECS 平均 CPU 连续高于 60% 或高峰 P95 不达标:升配或启用 AS。
- 服务数超过 5 个、每周多次发布或需自动扩缩容:迁移 VKE。
- 异步任务出现积压、重试和削峰需求:引入 RocketMQ。
- 单地域故障不可接受:RDS/DTS + TOS 跨区域复制 + GTM 建设双地域灾备。

## 12. 实施阶段

### 阶段 1:账号与网络

### 阶段 3:应用与流量

- 部署双 ECS、ALB、WAF、CDN 和四个域名。
- 接入短信签名/模板/回调与微信生产应用。

### 阶段 4:观测与上线

- 接入 TLS、CloudMonitor、VMP 和告警联系人。
- 完成压测、安全测试、故障切换、备份恢复和真实短信全链路验收。
- 灰度放量并连续观察错误率、延迟、短信和订单指标。
