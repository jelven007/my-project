# 小米汽车系统非功能与上线验收测试

> **版本:** v1.0
> **日期:** 2026-09-17
> **关联:** [测试总计划](./2026-09-17-test-plan.md) | [火山引擎部署技术方案](../architecture/2026-09-17-volcengine-deployment-technical-design.md)

## 1. 目标

验证系统在火山引擎生产等价环境中满足 100 人持续并发、200 人短时冲击、安全防护、跨可用区高可用、备份恢复、监控告警、发布回滚和客户端兼容性要求。

非功能测试不得直接对生产执行破坏性操作。单机摘除、数据库切换、Redis 切换和恢复演练在 UAT 完成,生产只执行经过审批的只读检查和受控冒烟。

## 2. 环境与监控准备

### 2.1 生产等价 UAT

| 组件 | 要求 |
|------|------|
| 流量入口 | DNS → CDN/WAF → ALB,与生产相同规则 |
| 应用 | 2 台跨可用区 `2C4G` ECS,每台 2 个 API Worker |
| 数据库 | MySQL 8.0 双节点 `2C8G`,100 GiB 起 |
| 缓存 | Redis 1 GiB 主备 |
| 存储 | 独立 TOS 桶,开启版本控制和服务端加密 |
| 可观测 | ALB/TLS 日志、CloudMonitor、VMP 和告警联系人 |
| 外部集成 | 独立短信消息组和微信测试应用 |

### 2.2 压测数据

- 1000 个门户测试用户,其中 100 个有有效订单、100 个有预约。
- 20 个后台管理员,覆盖全部系统角色。
- 5 个城市、20 个经销商、每车型至少 20 条库存记录。
- 预置不少于 10000 条订单、10000 条短信投递、5000 条预约和 100000 条审计记录。
- 专门准备库存为 1、全部占用、临近过期和停用资源数据。

### 2.3 采集指标

- 客户端:k6 请求数、RPS、P50/P95/P99、失败率、迭代时长。
- ALB:QPS、活跃连接、后端响应、4xx/5xx、健康实例数。
- ECS:CPU、内存、网络、负载、进程重启、事件循环延迟。
- MySQL:CPU、连接、慢查询、锁等待、IOPS、存储、主备状态。
- Redis:CPU、内存、连接、命中率、拒绝连接和切换事件。
- 业务:注册、登录、下定、库存冲突、预约、短信提交和 SSE 延迟。

## 3. 100 人并发性能测试

### 3.1 流量模型

100 个虚拟用户的业务比例:

| 业务 | 比例 | 主要接口 |
|------|------|----------|
| 浏览内容和车型 | 45% | `/api/content/*`,`/api/cars*` |
| 查询经销商和库存 | 20% | `/api/dealers`,`/api/inventory` |
| 登录和个人中心 | 10% | `/api/auth/login`,`/api/auth/refresh`,`/api/auth/me` |
| 0 元订单 | 10% | `/api/orders*` |
| 试驾预约 | 5% | `/api/test-drives*` |
| 后台查询 | 5% | Dashboard、用户、订单、库存 |
| 后台写入 | 5% | 内容、库存、订单状态 |

动态 API 稳态按 50 RPS、峰值按 100 RPS。每个虚拟用户使用独立会话;不可共享 Access Token、幂等键或购物数据。

### 3.2 性能用例

| ID | 优先级 | 步骤 | 通过标准 |
|----|--------|------|----------|
| NF-PERF-001 | P0 | 5 分钟从 0 升至 100 并发,按业务比例持续 30 分钟 | 读取 P95/P99 `≤300/800ms`;写入 `≤500/1200ms`;5xx `<0.1%` |
| NF-PERF-002 | P0 | 固定 100 RPS 持续 10 分钟 | 无请求队列失控、连接耗尽或进程重启 |
| NF-PERF-003 | P0 | 1 分钟升至 200 并发并持续 5 分钟,再恢复 100 | 读取 P95/P99 `≤800/1500ms`;写入 `≤1200/2500ms`;5xx `<1%` |
| NF-PERF-004 | P1 | 100 并发持续 4 小时 | 内存无持续增长,连接数回收,错误率无趋势性上升 |
| NF-PERF-005 | P1 | 100 用户同时冷启动门户 | 首屏资源主要由 CDN 命中,不冲击 ECS;单用户首屏不高于 3 MiB |
| NF-PERF-006 | P1 | 使用 100000 条审计和 10000 条订单执行后台筛选分页 | 常用查询 P95 不高于 500ms,无全表无界查询 |
| NF-PERF-007 | P1 | 10 条 Dashboard SSE 保持 60 分钟并持续产生业务事件 | 更新不超过 5 秒,无连接泄漏或重复统计 |
| NF-PERF-008 | P1 | 缓存冷启动后执行 100 并发读取 | 数据正确;MySQL 水位可控;缓存恢复后延迟回落 |

### 3.3 资源通过标准

| 资源 | 100 并发 | 200 并发冲击 |
|------|----------|----------------|
| ECS CPU | 双机各 `<65%` | `<85%`,结束 2 分钟内回落 |
| ECS 内存 | 各 `<75%` 且无增长泄漏 | `<85%`,无 OOM |
| MySQL CPU | `<60%` | `<80%` |
| MySQL 连接 | `<60%` | `<75%` |
| Redis CPU/内存 | `<50% / <60%` | `<75% / <70%` |
| ALB | 2 个健康实例,无异常 502/504 | 无后端全部失健康 |

业务校验失败和预期 `4xx/429` 单独统计。火山引擎短信和微信外部耗时单独分桶,不得将其计入普通内部 API 延迟。

## 4. 并发与一致性

| ID | 优先级 | 步骤 | 预期结果 |
|----|--------|------|----------|
| NF-CON-001 | P0 | 库存仅 1,100 个用户同时创建订单 | 仅 1 个成功;`reserved_qty≤total_qty`;无重复订单 |

## 5. 安全测试

测试遵循授权范围,禁止对非测试账号、生产数据或第三方服务执行攻击性扫描。

| ID | 优先级 | 测试 | 预期结果 |
|----|--------|------|----------|
| NF-SEC-001 | P0 | SQL 注入覆盖查询、登录、筛选和排序参数 | 无注入;错误不泄露 SQL、表名或堆栈 |
| NF-SEC-002 | P0 | 反射型、存储型和 DOM XSS 覆盖 CMS、昵称、备注 | 脚本不执行;危险内容拒绝或净化 |
| NF-SEC-003 | P0 | 使用用户 A 标识访问用户 B 的订单、预约、资料 | IDOR 被阻止且无存在性泄露 |

| NF-SEC-005 | P0 | CSRF 攻击后台状态变更接口 | Origin/CSRF 校验阻止请求 |
| NF-SEC-006 | P0 | 篡改、过期和重放 JWT/Refresh Token | 认证失败,旋转后的旧 Token 不可用 |
| NF-SEC-007 | P0 | 篡改或重放微信 state/code | 不建立会话或身份绑定 |
| NF-SEC-008 | P0 | 伪造短信状态报告 | 错误令牌、账号、消息组、MessageID 或时间窗均被拒绝 |
| NF-SEC-009 | P0 | 上传 SVG、HTML、双扩展名、伪造 MIME、超限图片 | 后端文件头和限制校验阻止发布 |
| NF-SEC-010 | P0 | 检索前端包、镜像、环境文件、API、TLS 和数据库 | 无密码、验证码、Token、Cookie、AppSecret、AK/SK 或完整手机号 |
| NF-SEC-011 | P1 | 高频请求登录、短信、微信回调和下定 | WAF 与应用双层限流生效,不影响普通静态访问 |
| NF-SEC-012 | P1 | 检查 TLS、CORS、CSP、HSTS 和 Cookie 属性 | 仅 HTTPS;来源白名单和安全响应头正确 |
| NF-SEC-013 | P1 | 绕过 WAF 直接访问 ECS/ALB 源站 | ECS 无公网入口;非预期源站访问被安全组拒绝 |
| NF-SEC-014 | P1 | 检查 IAM、ECS 角色和 Secret Manager | 最小权限;测试与生产隔离;凭据读取有审计 |
| NF-SEC-015 | P1 | 执行依赖和镜像漏洞扫描 | 无未豁免的 Critical/High 漏洞 |

## 11. 上线前验收清单

### 11.1 业务

- [ ] 门户和后台冒烟集连续 3 次通过。
- [ ] 手机号注册、密码登录、验证码登录和微信登录通过。
- [ ] 真实短信发送、接收、一次性消费和状态报告闭环通过。
- [ ] 0 元下定、取消、过期和完成的库存变化正确。
- [ ] 内容发布后门户 60 秒内生效,草稿不泄露。
- [ ] Dashboard 在注册或下定后 5 秒内更新。

### 11.2 性能与稳定性

- [ ] `NF-PERF-001` 至 `NF-PERF-008` 全部通过。
- [ ] `NF-CON-001` 至 `NF-CON-008` 全部通过。
- [ ] 单台 `2C4G` ECS 可承接完整 100 并发;否则已升至 `4C8G` 并重新压测。
- [ ] 单机故障、MySQL 切换和 Redis 切换完成演练。

### 11.3 安全与运维

- [ ] 无开放 S0/S1 和未豁免的 Critical/High 漏洞。
- [ ] WAF、CORS、CSP、HTTPS、Cookie、IAM 和安全组检查通过。
- [ ] Secret Manager、日志脱敏和审计检查通过。
- [ ] MySQL 时间点恢复和 TOS 版本恢复通过。
- [ ] 关键告警完成触发与恢复通知演练。
- [ ] API、数据库 migration、门户和后台均完成回滚演练。

## 12. 生产上线后验证

上线后 30 分钟内仅使用受控账号执行:

1. 检查 DNS、HTTPS 证书、CDN、WAF 和 ALB 健康状态。
2. 浏览首页、车型、经销商和库存。
3. 使用受控手机号发送 1 次真实注册或登录验证码。
4. 使用已绑定微信账号完成 1 次登录。
5. 创建并取消 1 个测试 0 元订单,核对库存恢复。
6. 创建 1 条试驾预约并在后台更新状态。
7. 发布并回滚 1 条专用测试内容。
8. 检查 Dashboard、TLS 日志、审计记录和告警状态。

若出现认证不可用、订单/库存不一致、敏感数据泄露、5xx 持续超阈值或健康实例少于 2 台,立即停止放量并按回滚方案处理。
