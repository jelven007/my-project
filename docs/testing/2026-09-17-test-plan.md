## 2. 测试目标

- 验证门户、后台、共享 API 和数据模型满足需求基线。
- 验证手机号注册、火山引擎真实短信、微信授权登录可用于正式环境。
- 验证人工库存、0 元下定、取消、过期和完成流程不会超卖或重复释放。
- 验证后台 RBAC、MFA、内容发布、审计和敏感数据保护有效。
- 验证 100 人并发、100 RPS 峰值和 200 并发冲击下达到性能指标。
- 验证火山引擎双可用区部署、日志告警、备份恢复、发布回滚和单机故障切换。

## 3. 测试范围

### 3.1 包含

| 测试域 | 范围 |
|--------|------|
| 门户页面 | 首页、车型详情、交付门店选择、注册、登录、微信授权、订单、试驾、个人中心 |
| 门户 API | 认证、内容、车型、交付门店、订单、试驾 |
| 后台页面 | Dashboard、内容、车型、经销商、库存、订单、媒体、用户、预约、管理员、角色、审计、短信监控 |
| 后台 API | 管理员认证、RBAC、发布、库存、订单、用户、预约、Dashboard、短信、审计 |
| 外部集成 | 火山引擎短信、微信开放平台、TOS、CDN、Secret Manager |
| 数据一致性 | MySQL 事务、行锁、乐观锁、Token 旋转、订单过期任务 |
| 非功能 | 兼容性、可访问性、安全、性能、稳定性、容灾、备份恢复、可观测性 |

### 3.2 不包含

- 在线支付、退款、发票和购车合同。
- ERP/DMS 自动同步和 Excel 批量库存导入。
- 微信以外的第三方登录。
- 多语言和多租户。
- VKE、RocketMQ、GTM 等后续扩展能力。

## 4. 测试策略

| 层级 | 执行对象 | 建议工具 | 门禁 |
|------|----------|----------|------|
| 静态检查 | 前后端代码、依赖、配置 | ESLint、TypeScript、npm audit、secret scanner | 无高危问题 |
| 单元测试 | 校验器、状态机、权限、库存计算、Token、短信适配器 | Vitest/Jest | 关键模块分支覆盖率不低于 80% |
| API 集成 | Express API、MySQL、Redis、短信/微信契约 | Supertest、Testcontainers 或独立测试库 | 全部 P0/P1 通过 |
| UI 组件 | 表单、表格、权限组件、错误状态 | Testing Library | 核心交互通过 |
| E2E | 门户和后台主流程 | Playwright | 冒烟集每次发布通过 |
| 性能 | 100/200 并发和单机故障 | k6、CloudMonitor、VMP | 满足技术方案第 10 节 |
| 安全 | OWASP、认证授权、文件上传、敏感信息 | ZAP/Burp、依赖扫描、人工验证 | 无未关闭高危/严重问题 |
| 灾备 | ECS、MySQL、Redis、TOS、回滚 | 火山引擎控制台与脚本 | 达到 RPO/RTO |

## 5. 测试环境

### 5.1 环境矩阵

| 环境 | 用途 | 外部服务 | 数据规则 |
|------|------|----------|----------|
| Local/CI | 单元和 API 快速反馈 | SMS/微信使用契约 Mock | 每次运行自动创建并清理 |
| Test | 功能、接口、E2E | 独立测试短信配置;微信沙箱或测试应用 | 可重复构造,禁止生产数据 |
| UAT | 业务验收、真实短信、生产等价压测 | 火山引擎真实短信和微信测试应用 | 脱敏账号,性能测试后清理 |
| Production | 上线冒烟和监控验证 | 正式短信和微信应用 | 仅受控测试账号,禁止破坏性测试 |

### 5.2 UAT 生产等价要求

- 2 台跨可用区 `2C4G` ECS,经 WAF 和 ALB 接入。
- MySQL 8.0 双节点 `2C8G`,Redis 1 GiB 主备。
- 前端和媒体通过 TOS + CDN。
- TLS、CloudMonitor、VMP 和告警通知均启用。
- 与生产使用相同配置结构,但域名、数据库、TOS 桶、短信消息组、微信应用和密钥完全隔离。

## 6. 测试数据

### 6.1 基础数据

| 数据 | 最小准备量 |
|------|------------|
| 车型 | 3 个已发布、1 个草稿、1 个下线 |
| 经销商 | 2 个城市各 2 个启用、1 个停用 |
| 库存 | 有库存、零库存、全占用、停用四类 |
| 门户用户 | 正常、禁用、锁定、微信已绑定、微信未绑定各 1 个 |
| 管理员 | 每个系统角色至少 1 个,超级管理员至少 2 个 |
| 订单 | 每种状态至少 3 条,另准备临近过期订单 |
| 预约 | 每种状态至少 2 条 |
| 内容 | 草稿、已发布、历史版本和引用媒体各 1 组 |
| 媒体 | 合法 JPG/PNG/WebP、超限文件、伪装 MIME、SVG/HTML |

### 6.2 数据安全

- 测试手机号须获得持有人授权;真实短信测试建立号码白名单和每日上限。
- 不从生产复制明文手机号、微信标识、Token、密码或管理员 MFA 密钥。
- 自动化账号使用随机后缀并记录清理批次。
- 性能测试订单、用户、预约和审计数据使用专用前缀,测试后按事务安全清理。

## 8. 优先级与缺陷等级

### 8.1 用例优先级

| 优先级 | 定义 |
|--------|------|
| P0 | 无法上线的核心链路:登录、短信、下定、后台库存一致性、后台登录/权限、发布 |
| P1 | 主要业务与安全控制,失败会显著影响用户或运营 |
| P2 | 次要功能、兼容性、易用性和低频异常 |

### 8.2 缺陷等级

| 等级 | 示例 | 上线要求 |
|------|------|----------|
| S0 阻断 | 数据损坏、超卖、认证绕过、大面积不可用 | 必须修复 |
| S1 严重 | 核心流程不可用、敏感数据泄露、权限提升 | 必须修复 |
| S2 一般 | 有规避方案的主要功能错误、明显兼容问题 | 原则上修复 |
| S3 轻微 | 文案、低影响样式或易用性问题 | 评估后处理 |

## 10. 执行与报告

### 10.1 测试轮次

1. 冒烟:部署后 30 分钟内验证登录、内容、交付门店选择、下定和后台库存管理。
2. 功能轮次:执行门户和后台全部 P0/P1/P2。
3. 回归轮次:缺陷修复后执行受影响模块及核心 E2E。
4. 非功能轮次:性能、安全、容灾、备份和监控演练。
5. 上线验收:真实短信、微信授权、生产配置核查和只读冒烟。

### 10.2 证据要求

- 每条失败用例记录版本、环境、账号类型、请求 ID、时间和复现步骤。
- API 问题附请求/响应并脱敏;禁止附验证码、Token、Cookie 或完整手机号。
- UI 问题附截图或录像;性能问题附脚本版本、负载模型和 CloudMonitor/VMP 图表。
- 数据一致性问题附事务前后关键记录,但敏感字段必须脱敏。

### 10.3 测试报告

最终报告至少包含:

- 测试范围、版本和环境。
- 用例总数、通过率、阻塞数和未执行原因。
- 按模块和严重级别统计的缺陷。
- 性能目标与实测对比。
- 安全、容灾、真实短信和微信验收结论。
- 遗留风险、上线建议、签字人与日期。
